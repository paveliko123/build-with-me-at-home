Usage experiment (E3)

The same scripted Kid session, run three ways on your own Claude plan: Start → Idea → Design → Tech plan with the same answers (one naughty request, one name and school), one build, one round of changes and the edit. Every run started with a cold cache. Measured 06/10/2026, 15:06:15.

What we learned

  • Does claude -p get the 1-hour cache? Yes: every token written to the cache went to the 1-hour cache.
  • Can a check share the guide's cache? Only as an exact fork. Claude Code turns --json-schema into a tool, and tools come first in the cache, so a check with its own reply format misses the guide's cache completely. Mix B's checks reuse the guide's reply format and read its cached instructions.
  • What the cache holds: each turn sends the conversation as one new message, so what's reused is the step's instructions (thousands of tokens, the same every turn), not the conversation.
  • Plan usage: one whole app took 2–3% of the 5-hour limit in every mix, and the weekly % didn't move. /usage only shows whole percents, so the mixes can't be told apart that way: compare them by the cost estimate and the speed.
  • Cost: B costs 31% more than A, and C 71% more. Speed: B's turns are the fastest (8.1 s against 12.4 s for A), because the check of the guide's reply runs after the guide answers, and here the Sonnet fork answered faster than the Haiku check (2.8 s against 6.6 s).
